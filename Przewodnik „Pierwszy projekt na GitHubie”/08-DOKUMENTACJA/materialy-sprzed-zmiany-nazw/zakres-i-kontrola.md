# Kontrakt odbioru — ASD1-M2-12

Autor: Deividas Dirma. Temat: Przewodnik „Pierwszy projekt na GitHubie”.

## Cel i ograniczenia
Działająca lokalnie aplikacja zgodna z sześcioma regułami, minimalistycznym projektem interfejsu oraz wymaganiami ASD I. Czyste HTML/CSS/JavaScript, bez kont, sieciowego API i frameworków. Kod jest pomocą do nauki i wymaga zrozumienia oraz weryfikacji przez autora przed obroną. Logo i kot są wyłącznie dekoracją; nie oznaczają oficjalnego produktu uczelni.

## Kryteria akceptacji
- Przykład kontrolny: 3/6, 50%, R5/R2/R6; po poprawieniu uruchomienia 4/6 i 66,7%.
- R1,R3,R5: błędy; R2,R4,R6: ostrzeżenia. R4–R6 niezależne od R3.
- Stabilne sortowanie przez wstawianie i wyszukiwanie pierwszego dopasowania w osobnych funkcjach; rzeczywiste liczniki.
- Formularz, przełączanie rekordów, porównanie poprzedniej kontroli z obecną, eksport README i raportu.
- Import z wersją formatu, pełna walidacja przed potwierdzeniem, brak częściowego zapisu.
- Do 1000 projektów i 1000 plików w projekcie, unikalne stabilne ID, ścieżki względne, bez wykonywania HTML użytkownika.
- Bez nieaktualnego wyniku przedstawianego jako aktualny: po edycji widoczny komunikat o poprzednim wyniku.
- Trzy scenariusze i dodatkowo przykład kontrolny/pusta lista.
- Testy uruchamiane poleceniem npm test; porównania uporządkowanych/odwróconych 10/100/1000 względem wzorca, wyszukiwanie początku/końca/braku.
- Materiały: README, dokładnie 10 stron dokumentacji PDF, dokładnie 10 slajdów, prawdziwe zrzuty działającej aplikacji.

## Poza zakresem
Logowanie do GitHuba, odczyt zdalnego repozytorium, hosting publiczny, płatne usługi, profile Python/JavaScript jako opcjonalne rozszerzenia.

## Zależność zewnętrzna przy oddaniu
Obowiązkowe repozytorium GitHub musi powstać na koncie właściciela, a prowadzący musi mieć dostęp. Bez połączonego konta nie można opublikować repozytorium ani wpisać prawdziwego URL. Nie wolno zastępować go fikcyjnym adresem.
